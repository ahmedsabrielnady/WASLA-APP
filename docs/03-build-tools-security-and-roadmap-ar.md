# وصلة — أدوات البناء والأمان وخطة التنفيذ

## 1. هل يمكن بناء المنصة مجانًا 100%؟

يمكن بناء نموذج أولي بتكلفة اشتراك صفرية باستخدام Free Tiers. لكن لا يصح وعد المشروع التجاري الكامل بأنه سيظل مجانيًا 100%؛ الرسائل النصية، WhatsApp Business API، بوابات الدفع، النطاق الخاص، النسخ الاحتياطي، الخرائط، التخزين، والذكاء الاصطناعي قد تتطلب تكلفة. كما أن حدود الخطة المجانية قابلة للتغيير.

### الاختيار العملي المبدئي

| الوظيفة | الاختيار | الاستخدام |
|---|---|---|
| الكود والمراجعة | GitHub Free | المستودع والفروع وPull Requests |
| الواجهة | React + TypeScript + Vite | تطبيق ويب موحد قابل للتثبيت PWA |
| قاعدة البيانات والمصادقة | مشروع Supabase الحالي | بداية التطوير بعد فحص الجداول وRLS |
| نشر الواجهة | Cloudflare Pages | نشر static build ونطاق pages.dev |
| الاختبارات | Vitest + Playwright | اختبارات منطقية وتدفقات متصفح |
| التوثيق | Markdown داخل GitHub | قرارات المعمارية والمخطط وخطة التشغيل |
| مراقبة الأخطاء | أدوات مفتوحة المصدر/خطة مجانية بعد مراجعة الخصوصية | لا ترسل بيانات صحية في سجلات الأخطاء |

### قيود يجب أخذها بجدية

- Supabase Free يعرض حاليًا 500MB لقاعدة البيانات لكل مشروع و50,000 مستخدم نشط شهريًا و5GB egress و1GB تخزين ملفات، وقد يوقف المشروع بعد أسبوع من قلة النشاط. الخطة المجانية لا توفر نسخًا احتياطية تلقائية. هذه مناسبة لتجربة محدودة، وليست ضمان استمرارية لنظام سجلات مرضى أو معاملات مالية.
- Cloudflare Pages Free يعلن حتى 500 build شهريًا. وإذا استخدمنا Workers Free، فحد الطلبات المنشور هو 100,000 طلب يوميًا ووقت CPU محدود. هذه حدود استخدام وليست سعة مضمونة.
- GitHub Pages غير مناسب لاستضافة وصلة التجارية؛ وثائق GitHub تنص على أنه غير مخصص أو مسموح به لاستضافة متجر إلكتروني أو SaaS تجاري مجانًا.
- Vercel Hobby مخصص للاستخدام الشخصي وغير التجاري؛ لا نعتمده كاستضافة إنتاج مجانية لمنصة تجارية.
- نطاق pages.dev مجاني، أما نطاق خاص مثل wasla.com فيتطلب غالبًا شراء وتجديدًا.

**القرار:** لا نغيّر Supabase الآن ولا ندفع. نستخدمه لتطوير واختبار محدود، ونؤجل إدخال ملفات المرضى الحقيقية أو تشغيل مالي حقيقي حتى تتوفر ضوابط البيانات والنسخ الاحتياطي والامتثال.

## 2. الخصوصية والقوانين المصرية

هذه قائمة هندسية أولية وليست فتوى قانونية. يجب مراجعة محامٍ مصري مختص قبل معالجة بيانات صحية أو تشغيل الدفع والأدوية.

1. قانون حماية البيانات الشخصية رقم 151 لسنة 2020 ولائحته التنفيذية بقرار 816 لسنة 2025 ينظمان معالجة البيانات إلكترونيًا. تنص المادة 12 على قيود إضافية للبيانات الحساسة، ومنها البيانات الصحية، بما في ذلك الترخيص والموافقة الصريحة المكتوبة وفق الحالات التي يجيزها القانون.
2. فترة توفيق الأوضاع المرتبطة باللائحة التنفيذية انتهت في أواخر أكتوبر/بداية نوفمبر 2026 بحسب الإشعارات القانونية المنشورة؛ تاريخ اليوم 20 نوفمبر 2026، لذلك لا يجوز تأجيل مراجعة متطلبات مركز حماية البيانات الشخصية.
3. بيانات الأطفال تُعامل بحساسية خاصة؛ يجب إشراك ولي الأمر والتحقق من الموافقة قبل إنشاء ملفات تعليمية شخصية أو تتبع نشاط القاصر.
4. قانون حماية المستهلك رقم 181 لسنة 2018 يفرض إفصاحًا واضحًا عن المورد والسلعة والسعر والضمان وخدمات ما بعد البيع وموعد ومكان التسليم، وفق نطاق تطبيقه.
5. المادة 33 من قانون مزاولة مهنة الصيدلة رقم 127 لسنة 1955 تربط صرف الوصفة الطبية بصدورها من ممارس مرخص. الوصفة التي يرفعها المستخدم يمكن نقلها إلى صيدلية مرخصة بموافقته؛ لا يجوز للمنصة تشخيص الحالة أو تغيير الوصفة أو الحلول محل الصيدلي.
6. لا تنشئ محفظة أو تحتفظ بأموال العملاء كرصيد قابل للتحويل في المرحلة الأولى دون مراجعة متطلبات البنك المركزي ومقدم خدمات الدفع المرخص. استخدم مقدم دفع مرخصًا عندما يحين وقت الربط.

### ضوابط البيانات المطلوبة

- سجل موافقة مستقل لكل غرض ونسخة سياسة خصوصية.
- تقليل البيانات إلى الحد الضروري لكل خدمة.
- ملفات المريض في Storage خاص، مع وصول مؤقت موقّع.
- RLS حسب المستخدم والعيادة والطبيب والعلاقة العلاجية.
- سجل تدقيق لعرض وتعديل وتنزيل الملفات الطبية.
- تشفير النقل والتخزين، وفصل الأسرار عن الواجهة.
- منع بيانات المرضى من الظهور في logs أو أدوات analytics العامة.
- إجراءات وصول وتصحيح وتصدير وسحب موافقة واحتفاظ وحذف وفق القانون.
- اتفاقيات معالجة بيانات مع مقدمي الخدمة ومزودي التقنية عند لزومها.
- مراجعة مكان الاستضافة ونقل البيانات عبر الحدود والترخيص المطلوب.

## 3. لوحة المؤسس

يجب أن تكون واجهة تشغيل وإدارة لا صفحة أرقام تجميلية.

- Overview: الطلبات والحجوزات والإيراد والعمولات والتسويات والشكاوى.
- Providers: مراجعة وتفعيل وتعليق وحظر مقدمي الخدمة وفروعهم وتراخيصهم.
- Sectors: تشغيل/تعطيل قطاع أو خدمة أو منطقة تغطية.
- Orders: متابعة الأحداث والتأخر والإلغاء والنزاعات.
- Money: الإيرادات المستحقة والمحصلة والمستردة والمبالغ المستحقة للشركاء.
- Risk & Compliance: انتهاء التراخيص، الموافقات، طلبات الوصول للبيانات، حالات الخصوصية.
- Marketing: الحملات والأكواد والإحالات وتكلفة اكتساب العميل.
- Reports: يومي وأسبوعي وشهري حسب القطاع والمنطقة ومقدم الخدمة.
- Settings: الأسعار والعمولات والحدود وسياسات الإلغاء بعد سجل اعتماد.
- Audit: من فعل ماذا ومتى ولماذا.

يجب توفير صلاحيات موظفين جزئية؛ ليس كل موظف مؤسسًا. لا تمنح موظف الدعم صلاحية رؤية ملف المريض الكامل أو تعديل سجل مالي.

## 4. اختبار كل رحلة قبل الإطلاق

### الحساب

- تسجيل جديد، تكرار البريد/الهاتف، التحقق، إعادة تعيين كلمة المرور.
- دخول صحيح وخاطئ، انتهاء الجلسة، الخروج، الدخول من جهاز آخر.
- منع العميل من ترقية نفسه إلى طبيب أو مؤسس.
- منع قراءة بيانات مستخدم آخر عبر تغيير ID في الطلب.

### السوق والمطاعم

- منتج غير متاح، نفاد آخر وحدة، تغيير السعر بعد إضافة السلة.
- ضغط مستخدمين على آخر قطعة في الوقت نفسه.
- سلة من متجرين وتقسيمها لطلبات فرعية أو منع المزج بوضوح.
- تعديل الكمية، رسوم التوصيل، الحد الأدنى، الكوبون.
- رفض الطلب، الإلغاء، الاسترداد، تكرار الإرسال عند ضعف الشبكة.

### الطب

- منع الموعد المكرر والمتداخل.
- مناطق زمنية وتوقيت مصر والتواريخ الماضية.
- إلغاء ضمن وخارج المهلة.
- صلاحيات طبيب ومساعد عيادة ومريض.
- مريض لا يرى ملف مريض آخر.
- تذكير الموعد وفشل قناة الرسائل.
- وصفة لا تُعرض إلا للصيدلية التي وافق المريض على مشاركتها معها.

### التوصيل والصيانة والسيارات

- GPS ناجح ومرفوض وغير متاح.
- حفظ إحداثيات الاستلام والتسليم والعناوين اليدوية.
- تعيين المندوب، تعذر الوصول، إلغاء، إثبات الاستلام والتسليم.
- عرض سعر واعتماد العميل قبل بدء الإصلاح.
- اختلاف السعر أو تغيير قطع الغيار.
- تحصيل نقدي وتسوية المندوب.

### الأمان والاعتمادية

- XSS وSQL injection ومحاولات تجاوز RLS.
- Rate limiting ومحاولات دخول متكررة.
- إعادة تشغيل نفس العملية دون تكرار الدفع أو الطلب.
- انقطاع الشبكة وفشل الإشعارات.
- استعادة نسخة قاعدة البيانات والملفات.
- اختبارات موبايل وشاشات RTL وإمكانية الوصول.
- فحص تسرب المفاتيح والبيانات الحساسة داخل logs.

لا يوصف أي اختبار بأنه ناجح إلا بعد تشغيله وتسجيل النتيجة والبيئة والنسخة.

## 5. خطة التنفيذ وبوابات القبول

### المرحلة صفر — الأساس والتدقيق
- تم إنشاء فرع مستقل للتوثيق والتخطيط.
- تثبيت تقييم الكود الحالي.
- الحصول على تعريف مخطط Supabase وسياسات RLS ومراجعتها قبل migration.

**بوابة القبول:** فهم الجداول الحالية وعدم الكتابة فوق بيانات أو سياسات موجودة دون مراجعة.

### المرحلة الأولى — منصة الهوية والنواة
- React/TypeScript، نظام تصميم RTL، التنقل، الحسابات والأدوار.
- ملفات المستخدم والمنشأة ومقدم الخدمة.
- الإعدادات وسجل التدقيق.
- migrations وCI واختبارات RLS.

**بوابة القبول:** كل دور لا يستطيع الوصول إلا لما يخصه.

### المرحلة الثانية — التجارة والطلبات
- كتالوج المتاجر والأسعار والمخزون والسلة والطلبات والتوصيل.
- إدارة التاجر والطلبات والعمليات المالية الأساسية.

**بوابة القبول:** شراء واكتمال وتسوية طلب تجريبي دون تكرار أو ضياع مخزون.

### المرحلة الثالثة — الحجوزات الطبية
- سجل الطبيب والعيادة والجدول والمواعيد والطابور والتنبيهات.
- موافقات المريض والملف الطبي بأقل بيانات لازمة.

**بوابة القبول:** اختبار تداخل وحجز وإلغاء وتذكير وصلاحيات ببيانات اصطناعية.

### المرحلة الرابعة — بقية القطاعات
- التعليم، الصيانة، السيارات، التوصيل المستقل، التحاليل والأشعة والصيدليات.
- كل قطاع يمر باختبارات تشغيلية وقانونية مستقلة.

### المرحلة الخامسة — تجربة محلية محدودة
- شركاء تم التحقق منهم.
- عدد طلبات معلوم وتغطية جغرافية محددة.
- قياس الاقتصاديات والشكاوى والالتزام بالوقت.
- توسيع النطاق فقط بعد ثبوت هامش مساهمة موجب واستقرار التشغيل.

## 6. المهارات المطلوبة

- Product/Operations: تحويل مشاكل السوق إلى قواعد تشغيل واضحة.
- Full-stack TypeScript/React: بنية التطبيق والواجهات.
- PostgreSQL/Supabase: نموذج البيانات وRLS وmigrations.
- QA Automation: Playwright واختبارات الصلاحيات والتدفقات.
- Security/Privacy: مراجعة التطبيق والبيانات الصحية.
- Health operations: مراجعة إجراءات العيادات والصيدليات والمعامل.
- Local business development: التعاقد والتدريب وحل مشاكل التجار.
- Finance/Accounting: العمولات والتحصيل والتسوية والضرائب.

يمكن أتمتة جانب من التحليل والبرمجة والاختبار، لكن لا يمكن تعويض توقيع طبيب أو محامٍ أو محاسب أو اختبار ميداني فعلي للعمليات.
