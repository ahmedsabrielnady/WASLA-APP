## القرار التنفيذي

**لا يُعتمد الإطلاق العام المفتوح بعد.** النسخة الحالية تصلح للانتقال إلى تجربة تشغيل محدودة بعد إغلاق بوابات الأمان والتحقق اليدوي. لا يوجد ما يثبت حتى الآن رحلة مستخدم كاملة في متصفح بحسابات فعلية، أو اختبار استعادة نسخة احتياطية، أو تأمين حساب الإدارة بـ MFA.

## ما تم إنجازه

- P0: منع تكرار الطلب، آلة حالات، إنشاء الطلب، إسناد الطلب، تحديث مقدم الخدمة، وإلغاء العميل.
- CRM: مؤشرات العملاء والطلبات والدعم، Customer 360، العملاء المحتملون، المهام، التفاعلات، ومتابعة مقدمي الخدمة والتذاكر.
- Provider Workspace: مساحة لمقدم الخدمة تعرض الطلبات المسندة لحسابه فقط، وتسمح بانتقال الحالة من confirmed إلى in_progress ثم done عبر RPC.
- RLS: جداول CRM محمية، وجدول انتقالات الحالات لا يسمح بوصول مباشر لأدوار التطبيق.
- أضيفت فهارس المفاتيح الأجنبية التي أبلغ عنها Performance Advisor لجداول CRM.
- تم إصلاح اكتشاف روابط Vercel branch previews وNetlify deploy previews لمنع الكتابة إلى قاعدة الإنتاج من المعاينات، وكذلك من localhost.
- تم تحديث PWA shell إلى cache v4 وإضافة الوحدات الأساسية إلى قائمة التخزين المسبق.
- تم حصر الطلب العام في قاعدة البيانات على قطاعي maintenance وcar. التمريض والعيادات مؤجلان حتى مراجعة التعامل مع البيانات الصحية.
- تم تقوية quote_order بحيث لا يمكن تغيير السعر إلا والطلب ما زال new، مع تسجيل الانتقال new → confirmed.
- GitHub Actions نجح على آخر commit: فحص syntax لـ 12 ملف JavaScript، و21 اختبارًا من 21 دون فشل.

## نطاق التجربة العامة المقترح

مسموح مبدئيًا:
- الصيانة المنزلية.
- خدمات السيارات.

غير مفعّل للطلب العام:
- التمريض والعيادات: بيانات صحية حساسة، وتحتاج مراجعة الخصوصية والموافقات والالتزامات القانونية قبل استقبال بيانات حقيقية.
- التوصيل: لا توجد دورة شحنات ومندوبين مكتملة.
- المطاعم والمتاجر: لا توجد دورة مخزون/سلة متعددة البنود/تحصيل مكتملة.
- التعليم: لا يوجد دليل مدرسين معتمد أو حجز دروس متكامل.

## قيود التشغيل الحالية

- يوجد مقدم خدمة واحد معتمد ونشط من نوع technician، وهو المورد التشغيلي المتاح للصيانة والسيارات وقت الفحص. لا يوجد دليل على قدرة تشغيلية بديلة إذا تعذر عليه تنفيذ الطلب.
- يوجد طبيب معتمد ونشط، لكن القطاع الصحي مؤجل من الطلب العام.
- لا يوجد دفتر مدفوعات أو إثبات تحصيل؛ لا يجوز عرض قيمة الطلبات على أنها إيرادات محصلة.
- مساحة مقدم الخدمة لا تعرض رقم هاتف العميل في هذه النسخة؛ التنسيق الهاتفي يتم عبر فريق التشغيل.
- لا توجد إشعارات Push أو SMS أو WhatsApp تلقائية.
- لا يوجد تتبع مباشر للمندوب أو إثبات تسليم.

## ملاحظات الأمن المتبقية

1. Supabase Auth Leaked Password Protection ما زالت معطلة حسب Security Advisor. يلزم تفعيلها من إعدادات Authentication قبل فتح التسجيل العام.
2. يجب التحقق من أن حساب admin الحالي يخص مالك المنصة فعلًا، وتأمينه بعامل MFA. لا يُرقّى أي حساب عشوائي.
3. Security Advisor يعرض 26 دالة SECURITY DEFINER قابلة للتنفيذ من authenticated. هذه الملاحظة عامة وليست إثبات اختراق؛ الدوال الأساسية المستخدمة في الطلبات وCRM تتحقق من الهوية/الدور/الملكية، لكن يلزم استكمال مراجعة كل دالة قبل توسيع الصلاحيات.
4. يوجد تنبيه INFO بأن جدول order_status_transitions عليه RLS دون سياسات. هذا مقصود: لا توجد صلاحيات مباشرة لأدوار التطبيق، وتقرأه دوال قاعدة البيانات المصرح بها فقط.
5. Performance Advisor لا يعرض مفاتيح CRM أجنبية غير مفهرسة بعد الإصلاح. تبقى تنبيهات سياسات permissive متعددة وفهارس لم تُستخدم بعد؛ لا تُحذف الفهارس قبل وجود حركة فعلية وقياس.
6. يجب إثبات وجود نسخة احتياطية قابلة للاستعادة وتنفيذ اختبار Restore قبل تخزين بيانات تشغيلية حساسة.
