4. **المال:** لا تظهر جداول `payments` أو `refunds` أو `commission` أو `settlements` أو دفتر قيود مالي.

1. حسم أي مشروع Supabase هو مشروع الإنتاج المقصود، وعدم تغيير URL الواجهة قبل ذلك.

## ملحق 21 نوفمبر 2026 — إصلاح القراءة العامة وعزل بيانات الاختبار

### مشكلة ظهرت في المعاينة المنشورة

كانت واجهة الصفحة الرئيسية تعرض «لا توجد خدمات مطابقة» رغم أن جدول الخدمات يحتوي على 12 خدمة نشطة. فحص REST من المتصفح أوضح:

- `service_items`: HTTP 200، عدد 12.
- `offers`: HTTP 401، والخطأ `permission denied for function is_staff`.

السبب: سياسة `offers_read` كانت تسمح بدور anon لكنها تستدعي دالة إدارية لا يملك anon حق تنفيذها. وكانت الواجهة تجمع طلب الخدمات والعروض في `Promise.all`؛ فشل العروض أدى إلى إسقاط تحميل الخدمات أيضًا.

### الإصلاح

- فصل سياسات القراءة العامة `anon` عن سياسات `authenticated` للجداول العامة ذات المحتوى العام/الخاص.
- جعل العروض النشطة قابلة للقراءة العامة دون استدعاء دالة إدارية.
- جعل قراءة الملفات والطلبات والملاحظات والموافقات مقتصرة على authenticated حسب السياسات.
- فصل تحميل الخدمات عن تحميل العروض باستخدام `Promise.allSettled` حتى لا يخفي فشل العروض قائمة الخدمات.
- فحص REST من المتصفح بعد الإصلاح:
  - الخدمات: 200 / 12 سجلًا.
  - العروض: 200 / 4 سجلات.
  - مقدمو الخدمة العامة: 200 / سجلين.
  - جداول الدوام العامة: 200 / صفر سجلًا.

### عزل مقدمي الخدمة التجريبيين

أظهرت قاعدة البيانات 7 مقدمي خدمة، خمسة منهم يحمل اسمهم نصًا واضحًا بأنه تجريبي. أحد الأطباء التجريبيين مرتبط بخمسة حجوزات قائمة بحالة `new` ومواعيد مستقبلية. لم تُحذف هذه الحجوزات ولم يتم تغيير حالتها.

التغييرات:
- إضافة `providers.is_test` افتراضيًا `false`.
- وسم الخمسة ذوي الأسماء التجريبية فقط على أنهم `is_test=true`.
- استبعاد هذه السجلات من دليل مقدمي الخدمة العام ومن جداول الدوام العامة.
- منع `clinic_available_slots` و`book_clinic_slot` من إظهار/قبول الطبيب التجريبي.
- منع `assign_order` من تعيين طلبات جديدة لمقدم خدمة تجريبي.
- الإبقاء على تاريخ الطلبات الخمسة ومعلومات مقدم الخدمة القديمة دون حذف.

نتيجة الفحص بعد التعديل:
- مرشحان فقط للظهور في دليل مقدمي الخدمة العامة.
- صفر جداول دوام عامة متاحة حاليًا؛ لا توجد جداول طبيب معتمدة حتى الآن.
- خمسة طلبات قديمة مرتبطة بالطبيب التجريبي ما زالت محفوظة.

### اختبارات قاعدة البيانات والواجهة

- اختبار تعاقدي محدود لإنشاء طلب عبر `place_order` تحقق من حالة `new` وسجل الحدث، ثم تراجعت المعاملة ولم تترك طلبًا تجريبيًا.
- اختبار ملكية `my_order_tracking`: صاحب الطلب يستطيع رؤية طلبه، ومحاولة قراءة طلب عميل آخر مرفوضة.
- اختبار ملكية `set_order_location`: صاحب الطلب يستطيع تحديث إحداثياته، ومحاولة تحديث طلب مستخدم آخر مرفوضة؛ تم التراجع عن تعديل الاختبار.
- اختبار عزل مقدمي الخدمة: تعيين فني تجريبي رُفض، وحجز الطبيب التجريبي رُفض. لم تُضف طلبات جديدة.
- اختبار واجهة متصفح معزول باستخدام mock Auth وmock REST وmock GPS: **10/10 checks نجحت**. شمل عرض الكتالوج والعروض، فتح نموذج الطلب، التقاط GPS، بناء payload الصحيح، استدعاء RPC للطلب والموقع مرة واحدة لكل منهما، ظهور الطلب في سجل العميل وعلامة الموقع المحفوظ.
- هذا الاختبار المعزول لا يستخدم حسابًا حقيقيًا ولا ينشئ طلبًا في قاعدة الإنتاج.

### التحذيرات المتبقية

- Security Advisor: 19 دالة `SECURITY DEFINER` قابلة للتنفيذ من authenticated، إضافة إلى تعطيل Leaked Password Protection. يجب مراجعة الدوال كلٌ على حدة؛ لا تُسحب الصلاحيات جماعيًا حتى لا تتعطل عمليات التطبيق.
- Performance Advisor: سبع حالات Multiple Permissive Policies وعشر ملاحظات INFO لفهارس لم تُستخدم بعد. لم يظهر تحذير Unindexed Foreign Keys بعد إضافة الفهارس.

- لم يتم اختبار تسجيل الدخول الحقيقي أو إرسال بريد تأكيد أو تنفيذ طلب حقيقي من واجهة العميل.
