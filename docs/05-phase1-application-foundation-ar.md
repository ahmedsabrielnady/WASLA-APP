# وصلة — المرحلة الأولى: أساس التطبيق

**الفرع:** `app/phase-1-react-foundation`  
**قاعدة البيانات المعتمدة:** مشروع Supabase `wasla` — `yfgvimcqbtthnrbzbhft`  
**طبيعة التنفيذ:** تطبيق ويب/PWA ثابت، مقسم إلى JavaScript modules، دون حزم خارجية أو خطوة build.

## قرار تقني للمرحلة الأولى

اخترنا واجهة معيارية بملفات JavaScript ES Modules وواجهات المتصفح القياسية بدل إدخال إطار عمل وحزم كثيرة قبل اختبار رحلة المستخدم الأساسية. هذا يقلل الاعتماد على أدوات البناء والاشتراكات، ويمكن نشر النسخة على استضافة ملفات ثابتة. يمكن الانتقال إلى React/TypeScript لاحقًا دون تغيير قاعدة البيانات أو قواعد الخدمة.

لا يستخدم التطبيق مكتبة Supabase JavaScript؛ يتصل بـ Supabase Auth وREST/RPC عبر `fetch` مع المفتاح العام المخصص للواجهة. المفتاح public/publishable وليس سرًا. ممنوع إضافة `service_role` أو أي secret إلى ملفات المتصفح.

## ما تم بناؤه في هذه المرحلة

- صفحة رئيسية عربية RTL ومتجاوبة مع الهاتف والكمبيوتر.
- القطاعات الثمانية ضمن الواجهة مع تمييز ما يعمل وما هو قيد التجهيز.
- تحميل الخدمات النشطة وشريط الإعلانات من قاعدة البيانات الحية.
- تسجيل مستخدم بالبريد وكلمة المرور مع الاسم ورقم الهاتف في metadata، وتسجيل الدخول والخروج وتحديث الجلسة.
- حفظ موافقة الشروط والخصوصية عبر RPC قبل إرسال الطلب.
- إرسال طلبات للخدمات التي لها مسار RPC مدعوم حاليًا: التمريض المنزلي والصيانة وخدمات السيارات.
- عرض سجل طلبات العميل.
- لوحة تشغيل للموظفين المخولين تعرض أرقام الطلبات وحالاتها، قراءة فقط في هذه المرحلة.
- PWA shell cache للملفات الثابتة فقط. لا يتم تخزين استجابات Auth أو REST أو البيانات الخاصة offline.
- اختبارات وحدات للقطاعات والصلاحيات الظاهرة والتحقق من الهاتف والعنوان وهروب HTML.

## القطاعات التي لم تُفعّل بعد

- **العيادات:** توجد migration باسم `seed_test_doctor_schedule`، وبيانات الدوام لم تُعتمد كجداول حقيقية. لا يتم عرض مواعيد ولا إرسال حجز طبي منها.
- **الأسواق:** جدول المنتجات فارغ، ولم يُنشأ بعد نظام سلة متعددة البنود.
- **المطاعم:** لا يوجد كتالوج مطاعم/وجبات أو دورة تجهيز وتسليم مثبتة.
- **التعليم:** لا يوجد نظام حصص أو طلاب أو أولياء أمور.
- **التوصيل:** لا توجد شحنات أو إحداثيات أو تتبع مندوب أو إثبات تسليم.
- **المتاجر:** لا يتم بيع المنتجات حتى بناء الطلبات متعددة البنود وتسوية المخزون.

## حدود التشغيل والخصوصية

- لا يوجد دفع إلكتروني أو محفظة. إظهار عربون في الطلب لا يعني تحصيله.
- العنوان نصي في هذا الإصدار؛ GPS وعناوين محفوظة لا تزال غير مفعلة.
- شاشة التشغيل الحالية للقراءة فقط؛ لا تسمح بتغيير حالة طلب.
- لا ترفع ملفات مرضى أو تقارير طبية. لا يوجد bucket خاص حتى الآن.
- لا يتم عرض مقدمي الخدمة ذوي الأسماء التجريبية للمستخدمين.
- الموافقات يتم تسجيلها بإصدار `1.0` عند تفعيل الجلسة، ويجب مراجعة النص القانوني وتاريخ النسخة قبل الإطلاق العام.

## التشغيل والاختبار

المشروع لا يحتاج dependencies خارجية:

```bash
npm ci
npm run verify
```

للتشغيل المحلي استخدم خادم ملفات ثابت مثل:

```bash
python -m http.server 8080
```

ثم افتح `http://localhost:8080`. لا تفتح الملف مباشرة عبر `file://` لأن ES Modules وService Worker يحتاجان HTTP/HTTPS.

## GPS الاختياري لطلبات الخدمات

- أضيف زرًا اختياريًا لطلب إذن تحديد الموقع من الجهاز عند بدء الطلب.
- يظل حقل العنوان النصي موجودًا لأن قاعدة البيانات تشترطه؛ عند استخدام GPS يُقترح النص `موقعي الحالي` ويظل قابلًا للتعديل.
- بعد نجاح إنشاء الطلب فقط، يستدعي التطبيق `set_order_location` لحفظ `lat/lng` في نفس الطلب.
- إذا فشل حفظ GPS بعد إنشاء الطلب، لا يعيد التطبيق إرسال الطلب ولا يطلب من العميل تكراره؛ يعرض رسالة واضحة.
- تظهر علامة «تم تسجيل إحداثيات موقع التنفيذ» داخل سجل طلبات العميل.
- يستخدم Service Worker ذاكرة مؤقتة بإصدار جديد واستراتيجية Network-first لملفات التطبيق حتى لا يظل المتصفح عالقًا على JavaScript قديم بعد النشر.

## عزل بيانات مقدمي الخدمة التجريبية

أُضيف الحقل `providers.is_test`، وعُلّمت السجلات التي تحمل اسم «تجريبي» بهذا العلم دون حذف أي سجل أو تعديل الحجوزات القائمة. سياسات اكتشاف مقدمي الخدمة العامة والدوام العام تستبعد هذه السجلات. دوال الحجوزات وتعيين مقدم الخدمة ترفض استخدامها للعمليات الجديدة، مع الإبقاء على تاريخ الطلبات السابقة وإمكانية وصول أصحاب الحسابات إلى سجلاتهم.
